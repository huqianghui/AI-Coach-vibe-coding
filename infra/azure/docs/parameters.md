# Azure deployment parameters

Use `main.parameters.example.json` as a non-secret template only. Do not commit real secret values.

## Required decisions

| Parameter | Default | Notes |
|---|---:|---|
| `location` | `swedencentral` when using scripts | Confirm Azure OpenAI, Speech/Avatar, Content Understanding, and Foundry availability before deployment. |
| `environmentName` | `public` | Allowed values: `dev`, `demo`, `public`, `private`, `prod`. |
| `namePrefix` | `aicoach` | Keep lowercase and short. |
| `resourceGroupName` | generated by script | Optional. Leave empty to use `rg-{namePrefix}-{environmentName}-{location}`; pass `-ResourceGroupName` to deploy into a named group. |
| `deploymentMode` | `foundryOnly` | Allowed values: `foundryOnly`, `fullLegacy`. `fullLegacy` preserves the earlier broad deployment shape. |
| `networkProfile` | `publicDemo` | Allowed values: `publicDemo`, `privateBackend`. `publicDemo` keeps backend and frontend Container Apps publicly reachable for demo testing. `privateBackend` keeps frontend public, makes backend ingress internal, integrates Container Apps with a VNet, and creates private endpoints for the first private-backend path. |
| `vnetName` | empty | Optional existing VNet name for `privateBackend`. Leave empty to let Bicep create `vnet-{namePrefix}-{environmentName}`. |
| `vnetAddressPrefix` | `10.60.0.0/16` | Address space used only when `privateBackend` auto-creates the VNet. |
| `containerAppsSubnetPrefix` | `10.60.0.0/23` | Delegated Container Apps infrastructure subnet prefix used only for an auto-created VNet. |
| `privateEndpointsSubnetPrefix` | `10.60.2.0/24` | Private endpoint subnet prefix used only for an auto-created VNet. |
| `knowledgeBaseMode` | `none` | Allowed values: `none`, `azureAiSearch`. Azure AI Search is deployed only when this is `azureAiSearch`, `fullLegacy` is selected, or `enableAiSearch=true`. |
| `containerRegistryName` | generated by script | Must be globally unique, lowercase alphanumeric, 5-50 chars. |
| `storageAccountName` | generated by script | Must be globally unique, lowercase alphanumeric, 3-24 chars. |
| `postgresAdminPassword` | generated by script in default cloud mode | Must satisfy PostgreSQL password policy. Existing deployments are not read from Key Vault; pass/prompt the current password only when legacy password `DATABASE_URL` mode still needs it. |
| `jwtSecret` | generated by script on first deploy | Stable secret for JWT signing. Later deployments use Container App Key Vault references and do not read this secret locally. |
| `encryptionKey` | generated by script on first deploy | Fernet-compatible key for local/database encrypted config. Later deployments use Container App Key Vault references and do not read this secret locally. |
| `backendDatabaseAuthMode` | `azureAd` in script/example | `azureAd` configures backend env vars for Managed Identity / Entra token auth. Pass `password` only for legacy `DATABASE_URL` deployments. |
| `azureServiceKeyStorage` | `keyvault` in script/example | `keyvault` makes Admin UI write service keys to Key Vault. Pass `database` only for local/legacy encrypted DB service-key storage. |
| `postgresEntraAdminLogin` | current Azure CLI user in script | PostgreSQL Entra admin used to bootstrap DB roles. Prefer an Entra group for production. |
| `postgresEntraAdminObjectId` | current Azure CLI user in script | Object ID for the PostgreSQL Entra admin principal. |
| `postgresEntraAdminPrincipalType` | `User` | Allowed values: `User`, `Group`, `ServicePrincipal`. |
| `manageBootstrapSecrets` | `true` | Keep `true` only for first deployment or intentional secret rotation. Set/leave `false` for updates so Bicep does not rotate Key Vault bootstrap secrets or PostgreSQL admin password. |
| `databaseAutoCreateTables` | `false` | Keep disabled for production. With `-DeployApp`, the deployment script starts a backend Container Apps Job that runs schema migration through `backend\scripts\bootstrap_app.py`; this parameter exists only as an emergency/dev escape hatch. |
| `SkipDbBootstrap` script switch | `false` | In `azureAd` DB mode, the script automatically runs `backend\scripts\bootstrap_postgres_entra.py` after infra deployment. Pass this switch only when bootstrap should be handled separately. |
| `PostgresBootstrapClientIp` script parameter | current public IP | For `publicDemo` local DB bootstrap, the script temporarily allows this client IP through PostgreSQL firewall. Pass explicitly if automatic public IP detection is unavailable. |
| `KeepPostgresBootstrapFirewallRule` script switch | `false` | Keeps the temporary PostgreSQL bootstrap firewall rule after local bootstrap for troubleshooting. By default the rule is removed in `finally`. |
| `SkipAppBootstrap` script switch | `false` | Skips deployment-time Container Apps Job bootstrap for Alembic migration and sample data. Use only when another pipeline step already handles DB/schema/sample initialization. |
| `SkipSampleData` script switch | `false` | Runs schema migration but skips sample data seeding. |

## Image parameters

`backendImage` and `frontendImage` default to a public hello-world image so infrastructure can deploy before project images exist. `scripts\build-and-push.ps1` builds real images in ACR and updates Container Apps after the first deployment.

The Bicep deploys only the `gpt-4o` chat/scoring model under both the Foundry account and the separate Azure OpenAI account while the deployment remains in transition. Voice Live realtime models are selected by the app/Foundry runtime model whitelist and are not deployed as Bicep model deployments. Model versions and quota are region-sensitive. If deployment fails on model availability, change the chat model version or disable Azure AI for the first pass.

## Capability flags

The script default is `deploymentMode=foundryOnly`, `networkProfile=publicDemo`, and `knowledgeBaseMode=none`, which keeps Speech/Avatar, Content Understanding, and Azure AI Search out of the default footprint while leaving the demo endpoints public. Pass `-NetworkProfile privateBackend` to deploy the VNet-integrated private-backend path. Existing callers can still pass explicit boolean parameters to Bicep, and `deploymentMode=fullLegacy` enables the broader legacy set.

## Private backend DNS zones

`privateBackend` creates private DNS zones and links them to the deployment VNet. Foundry Tools (`Microsoft.CognitiveServices/accounts`, subresource `account`) is associated with all three zones that Azure Portal creates by default:

| Public host family | Private DNS zone |
|---|---|
| `*.cognitiveservices.azure.com` | `privatelink.cognitiveservices.azure.com` |
| `*.openai.azure.com` | `privatelink.openai.azure.com` |
| `*.services.ai.azure.com` | `privatelink.services.ai.azure.com` |

The app currently has code paths that can use both `cognitiveservices.azure.com` and `services.ai.azure.com`, so all three Foundry-related zones are required before disabling Foundry public network access.

## Cloud default security mode

The deployment script defaults to the security-hardened cloud path:

```powershell
.\infra\azure\scripts\deploy.ps1
```

When `backendDatabaseAuthMode=azureAd` and the admin login/object ID are omitted, the script uses the current Azure CLI signed-in user as the PostgreSQL Entra admin. For production, pass an Entra group explicitly:

```powershell
.\infra\azure\scripts\deploy.ps1 `
  -PostgresEntraAdminLogin "<admin-group-name>" `
  -PostgresEntraAdminObjectId "<admin-group-object-id>" `
  -PostgresEntraAdminPrincipalType Group
```

After infra deployment, the script automatically runs `backend\scripts\bootstrap_postgres_entra.py` as the configured PostgreSQL Entra admin to create/grant the backend Managed Identity DB role. The bootstrap uses the managed identity object ID to avoid ambiguous Entra display-name lookup. With `-DeployApp`, it then starts a backend Container Apps Job that uses the backend image and Managed Identity to run `backend\scripts\bootstrap_app.py` inside Azure, apply Alembic migrations, and idempotently seed sample SkillHub, HCP profile, scenario, and material records. You can change the PostgreSQL Entra admin later in Azure Portal, preferably to an Entra group or dedicated bootstrap identity.

For legacy password/DB-key storage compatibility, pass:

```powershell
.\infra\azure\scripts\deploy.ps1 `
  -BackendDatabaseAuthMode password `
  -AzureServiceKeyStorage database
```
