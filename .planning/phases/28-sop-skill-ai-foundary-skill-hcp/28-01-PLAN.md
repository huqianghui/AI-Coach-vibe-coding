<objective>
Register published Skills as first-class Azure AI Foundry entities. Adds Foundry sync
tracking columns to the Skill model, a dedicated Entra-ID-only `skill_foundry_service.py`
(the Skills preview API rejects API keys with 403 — no fallback is possible, unlike the
existing dual-mode `agent_sync_service`), and hooks it into the skill lifecycle
(`publish_skill` syncs, `archive_skill`/`delete_skill` remove the cloud entity).

**Revision note (cross-AI review, REVIEWS.md):** this plan was revised to fix a naming-collision
correctness/security bug (HIGH-2: `_sanitize_skill_name` had no uniqueness guarantee, risking
cross-skill cloud entity overwrite and wrong-entity deletion on archive) and to address two
MEDIUM concerns (blocking credential calls inside async code; unbounded inline sync latency on
publish). See the `<deliberate_decisions>` block below for what was fixed vs. explicitly accepted.

Purpose: Make Skill = independent Foundry entity per D-01, with publish-not-blocked /
training-not-interrupted failure semantics per D-06, and version-recoverable re-publish
per D-03 — using a Foundry entity name that is guaranteed unique per skill.
Output: Migrated Skill model, skill_foundry_service.py, wired lifecycle hooks, unit tests.
</objective>

2. `def _sanitize_skill_name(name: str) -> str` — lowercase, replace any run of
   non-`[a-z0-9-]` with `-`, collapse repeated `-`, strip leading/trailing `-`, truncate to
   64 chars (re-stripping trailing `-` after truncation), fallback to `"skill"` if empty.

3. `def _build_unique_foundry_name(name: str, skill_id: str) -> str` (**HIGH-2 fix** —
   `_sanitize_skill_name` alone has no uniqueness guarantee: two distinct local skills whose
   names sanitize to the same slug would otherwise collide on the same Foundry entity, causing
   cross-skill cloud overwrite and, on archive, deletion of the WRONG skill's cloud entity. This
   function is used ONLY on first sync, per the caller logic in step 5 below; once
   `foundry_skill_name` is persisted it is reused verbatim on every subsequent sync):
   - `suffix = "-" + skill_id[:8].lower()` (8 lowercase hex chars from the UUID primary key —
     already pattern-safe, no further sanitizing needed).
   - `sanitized_name = _sanitize_skill_name(name)`.
   - `max_name_len = 64 - len(suffix)`; `name_part = sanitized_name[:max_name_len].rstrip("-")`
     (truncate FROM THE NAME, never from the suffix, and re-strip any trailing `-` left by
     truncation so the suffix's leading `-` can never produce `--`).
   - If `name_part` is empty after stripping, use `"skill"` as the fallback name part.
   - Return `f"{name_part}{suffix}"` — guaranteed `<=64` chars, matches
     `^[a-z0-9]([a-z0-9-]*[a-z0-9])?$`, contains no `--`, and is unique per skill because
     `skill_id` is a UUID primary key.
