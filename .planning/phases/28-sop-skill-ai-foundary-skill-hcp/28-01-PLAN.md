tracking columns to the Skill model, a dedicated Entra-ID-only `skill_foundry_service.py`
(the Skills preview API rejects API keys with 403 — no fallback is possible, unlike the
existing dual-mode `agent_sync_service`), and hooks it into the skill lifecycle
(`publish_skill` syncs, `archive_skill`/`delete_skill` remove the cloud entity).

Purpose: Make Skill = independent Foundry entity per D-01, with publish-not-blocked /
training-not-interrupted failure semantics per D-06, and version-recoverable re-publish
per D-03.
Output: Migrated Skill model, skill_foundry_service.py, wired lifecycle hooks, unit tests.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend → Azure AI Foundry Skills API | Entra ID bearer token sent to external preview endpoint; ZIP bytes uploaded |
| Skill DB content → ZIP → Foundry | Locally-authored skill content becomes a cloud-hosted, agent-consumable artifact |
| Admin action → lifecycle hook | publish/archive/delete triggers outbound network calls as a side effect |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-01 | Spoofing / Improper Auth | get_skills_client | mitigate | Entra-ID-only, no API-key branch exists (unlike agent_sync_service); explicit RuntimeError on credential failure rather than a silent insecure fallback |
| T-28-02 | Tampering | ZIP content uploaded via create_from_files | mitigate | Reuse skill_zip_service.validate_zip_security() before every upload — defense-in-depth even though the ZIP is server-generated from trusted DB content |
| T-28-03 | Information Disclosure | foundry_sync_error stored/returned | mitigate | Field only ever exposed via admin-only routes (existing require_role("admin") pattern in skills.py, wired in Plan 28-03); truncated to 2000 chars to avoid leaking oversized stack traces |
| T-28-04 | Denial of Service | Foundry API latency/errors on publish | mitigate | sync_skill_to_foundry never raises and never retries in a loop; publish_skill() is non-blocking per D-06 |
| T-28-05 | Elevation of Privilege | Triggering Foundry sync/delete | accept | Only reachable via publish_skill/archive_skill/delete_skill, which are already gated by require_role("admin") in skills.py — no new privilege surface introduced |
</threat_model>
