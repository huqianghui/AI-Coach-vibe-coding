# Phase 27 Plan 01: Prompt Registry Foundation Summary

**Versioned prompt registry (PromptTemplate/PromptVersion/PromptOptimizationRun) with a 9-key defaults catalog sourced from existing constants, an async `get_prompt()` resolver, and idempotent startup seeding.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 3
- **Files created:** 7
- **Files modified:** 3

## Accomplishments
- Three ORM models with Alembic migration `10096ff0a0af` (head advanced from `v29a_conference_prompt_config`)
- `PROMPT_DEFAULTS` catalog of all 9 project prompt keys, each backed by the real source constant where one exists
- `get_prompt(key)` resolver: returns active-version content or the seeded default, raises `KeyError` on unknown key
- `seed_prompt_registry()` idempotent seeding of version-1 (`source="seed"`, `is_active=True`) templates, wired into startup seed flow
- 8 unit tests, 100% coverage on `prompt_defaults.py` + `prompt_registry.py`

- `backend/tests/test_prompt_registry.py` - 8 unit tests (100% coverage)

## Decisions Made
- Version-reference columns are plain `String(36)` without FK constraints (only `template_id` keeps a real FK) to avoid circular-FK failures under SQLite `render_as_batch=True`.
- Defaults are imported from the existing constants so the registry stays in lock-step with current behavior and is snapshot-tested.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Autogenerated migration captured unrelated model/DB drift**
- **Found during:** Task 1
- **Issue:** `alembic revision --autogenerate` picked up pre-existing drift (scenarios columns/FKs, `score_details.category` NOT NULL, `voice_scores` index uniqueness) unrelated to the prompt registry.
- **Fix:** Manually rewrote the migration to create/drop only the 3 new prompt tables (both upgrade and downgrade).
- **Files modified:** `backend/alembic/versions/10096ff0a0af_add_prompt_registry_tables.py`
- **Verification:** `alembic upgrade head` applies cleanly; models import OK.
- **Committed in:** `6edefc0`

**2. [Rule 3 - Blocking] Circular-FK risk on version-reference columns**
- **Found during:** Task 1
- **Issue:** A real FK from `PromptTemplate.active_version_id` -> `prompt_versions.id` combined with `PromptVersion.template_id` -> `prompt_templates.id` risks circular-FK problems under SQLite batch migrations.
- **Fix:** Kept only `template_id` as a real FK; made `active_version_id`, `parent_version_id`, `base_version_id`, `resulting_version_id` plain `String(36)`.
- **Files modified:** the three model files
- **Verification:** migration applies; 8 tests pass.
- **Committed in:** `6edefc0`

**3. [Rule 1 - Adaptation] `hcp.system` has no single source constant**
- **Found during:** Task 2/3
- **Issue:** The HCP system prompt and key-message detection prompt are dynamically composed in `prompt_builder.py`, so there is no single constant to snapshot exactly.
- **Fix:** Defined `{{placeholder}}`-token templates for those two keys; snapshot test asserts `scoring.base == SCORING_PROMPT_TEMPLATE` exactly, and asserts structural markers + seed round-trip equality for `hcp.system`.
- **Files modified:** `backend/app/services/prompt_defaults.py`, `backend/tests/test_prompt_registry.py`
- **Verification:** 8 tests pass, 100% coverage.
- **Committed in:** `20aa06c`
