<objective>
Finish D-12: `resolve_voice_config()`'s no-VL-instance fallback branch currently reads 14 `HcpProfile` columns that Plan 29-05 deletes from the model (`voice_live_enabled`, `voice_name`, `avatar_character`, etc.) -- once that migration lands, this fallback branch is a live `AttributeError` waiting to fire for any HCP with no assigned Voice Live Instance. This plan replaces the fallback with a hardcoded safe-defaults dict, and deletes the now-dead "denormalized cache" write-sites in `update_instance()` / `assign_to_hcp()` that mirrored VL Instance avatar fields onto the (now-nonexistent) `HcpProfile.avatar_character`/`avatar_style`/`avatar_customized` columns.

This plan intentionally runs after Plan 29-05 (`depends_on: [1, 5]`) because its correctness is only meaningful once the columns are actually gone -- fixing the fallback branch before the columns are dropped would be premature, and dropping the columns before fixing this branch would break `resolve_voice_config()` for every unassigned HCP (used by `agent_sync_service.build_voice_live_metadata()` on every agent sync/resync call).

Purpose: Eliminate the last runtime dependency on the deleted inline voice/avatar columns inside the service layer, per D-12 ("agent sync voice metadata always sourced from VL Instance via resolve_voice_config(), remove inline-fallback branch reading deprecated columns").
Output: `resolve_voice_config()` with a column-free fallback; `update_instance()`/`assign_to_hcp()` with the dead avatar-mirror code deleted; 2 rewritten unit tests in `test_voice_live_instance_service.py` proving the new fallback values.
</objective>
