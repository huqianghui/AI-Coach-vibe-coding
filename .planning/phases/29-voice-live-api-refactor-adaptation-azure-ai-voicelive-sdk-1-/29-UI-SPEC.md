# Phase 29 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase type:** Primarily backend refactor (SDK upgrade, dual-path architecture, data model cleanup). The frontend surface is narrow and entirely reuse-driven — this contract locks 4 touchpoints only: (1) Voice/Avatar tab read-only VL summary + assign/unassign, (2) VL-required save-time validation, (3) connection-rejection error presentation, (4) new Agent Foundation Model dropdown states. **No new design language is introduced.** Every token, component, and copy pattern below is sourced from existing code (cited by file:line) — this document is a lock-in of existing conventions, not new invention.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — manual Tailwind v4 design-token system (no shadcn/`components.json`), established Phase 01 and audited through Phase 10 |
| Preset | not applicable |
| Component library | Radix UI primitives wrapped in local `frontend/src/components/ui/*` (forwardRef + `cn()` + `cva` pattern — Button, Badge, Select, Dialog, Form, Switch, Tooltip, Card) |
| Icon library | `lucide-react` ^0.460.0 |
| Font | `Inter` (Latin) + `Noto Sans SC` (Chinese) via `--font-sans`, defined in `frontend/src/styles/index.css:1,235` |

**shadcn gate decision:** No `components.json` exists anywhere in the repo (confirmed via `ls components.json` at repo root and `frontend/`). Per the phase's explicit scope instruction — *"Reuse existing patterns — this phase must NOT introduce new design language"* — the shadcn initialization prompt is **skipped by design**, not by oversight. Introducing shadcn now (28 phases into a project with an established, audited, Figma-sourced token system) would contradict the phase's own constraint and create two competing component systems. If shadcn adoption is ever desired, it should be its own dedicated phase with full audit — not smuggled into a backend refactor phase. Registry safety gate: not applicable.

## Component Contract — Voice/Avatar Tab Read-Only Summary (D-11)

Locks the exact structure `gsd-executor` must build, replacing the current editable "Model Deployment" selector + "Voice Mode" toggle block in `agent-config-left-panel.tsx:141-237`.

**Layout (reuses existing `Card`/`CardContent` shell, no new component):**

1. **VL Instance Summary Card** (replaces both the old "Model Deployment" Card and "Voice Mode" Card as a single consolidated card):
   - Header row: label `admin:hcp.vlInstanceLabel` ("Voice Live 实例") — 12px semibold, matches `text-xs font-semibold` convention (`agent-config-left-panel.tsx:144`)
   - **If assigned:** read-only summary line using `VoiceLiveInstanceSummary` (already defined in `frontend/src/types/hcp.ts:54-63` — no new type needed): instance name (bold) + 3 inline `Badge variant="secondary"` chips for `voice_live_model`, `voice_name`, `avatar_character`/`avatar_style` combined (e.g. `lori · casual`) — same chip pattern as the existing Select's `SelectItem` badge at `agent-config-left-panel.tsx:199`
   - **If unassigned:** empty-state copy (see Copywriting Contract) rendered in `text-muted-foreground`, plus required-field visual marker (red asterisk or `Badge variant="destructive"` reading "必填")
   - Action row: `Button variant="outline" size="sm"` "分配实例" (opens the same instance-picker `Select` used today, values sourced from `useVoiceLiveInstances()` — unchanged hook) + `Button variant="ghost" size="icon"` (X icon, destructive hover) for unassign, disabled/hidden when nothing is assigned
   - Link row: `Button variant="link" size="sm"` with `ExternalLink` icon → "前往 Voice Live 管理" — **verbatim reuse** of `agent-config-left-panel.tsx:219-227`, unchanged
2. **Foundation Model dropdown** (D-14, NEW — separate card, placed where "Model Deployment" card used to be, now decoupled from Voice Live model): `Select` component styled identically to `VoiceLiveModelSelect` (`h-8 text-xs` trigger) but sourced from the new `GET /api/v1/agent-foundation-models` endpoint via a new TanStack Query hook (e.g. `useAgentFoundationModels()`), with 3 explicit states per Copywriting Contract: loading (disabled + spinner-adjacent copy), error (retry affordance), empty (informational, non-blocking).
3. What is **removed**, not migrated: the "Voice Mode" `Switch` toggle (`agent-config-left-panel.tsx:156-236`) is deleted outright — since D-10 makes VL mandatory, "voice mode enabled/disabled" is no longer a meaningful toggle; voice capability is implied by having an assigned instance. The `voiceModeEnabled` prop threading through `voice-avatar-tab.tsx` and `playground-preview-panel.tsx` should collapse to a simple `Boolean(vlInstanceId)` derived value, not a separate stateful switch — **this is an implementation note for the planner, not a new interaction pattern.**

**Save-time validation (D-13):**
- `hcpSchema` in `hcp-profile-editor.tsx:79` changes `voice_live_instance_id: z.string().nullable().default(null)` → a `.refine()` (or non-nullable `z.string().min(1)`) that fails when empty, with a custom error message mapped to `admin:hcp.vlInstanceValidationError`.
- Error renders in the existing `FormField`/`FormMessage` slot (`frontend/src/components/ui/form.tsx:137-152`, `text-destructive text-sm` — already the established error-text style) directly under the VL Instance Summary Card.
- Submit-attempt-with-missing-VL also fires a `toast.error(...)` (Sonner, existing `sonner.tsx` component) — mirrors the exact call shape at `agent-config-left-panel.tsx:107`.
- Applies identically to create (`isNew=true`) and edit flows — no different treatment.

**Connection-rejection error (D-08):**
- Rendered as a `Card` with the "failed" status-color treatment (`bg-red-50 border-red-200`, `text-red-600` icon) lifted verbatim from `agent-status-section.tsx:36-41`.
- Appears in the voice session UI (wherever the current connection/mode error surface lives — e.g. adjacent to or replacing `ModeStatusIndicator`'s disconnected state) when the backend emits the new connection-rejection event for an unsynced HCP.
- Admin-facing surface (HCP editor context): includes a "重新同步 Agent" button wired to the existing `useRetrySyncHcpProfile()` mutation (already used by `agent-status-section.tsx:126-144` — no new mutation).
- End-user (MR) session surface: no retry button (MR has no sync permission) — informational only, directing to contact an administrator.
