<objective>
Split the Agent Foundation Model catalog (chat models backing the hosted Agent) away from the Voice Live realtime model catalog (`VOICE_LIVE_MODELS`, unchanged and untouched by this plan). Build a new admin-scoped, cached REST endpoint that dynamically pulls deployed chat models from AI Foundry via `AIProjectClient.deployments.list()` (data-plane, same endpoint/credential the app already stores — no ARM subscription/resource-group needed), and wire a new frontend dropdown into the HCP editor.

This plan runs in wave 4, after Plan 07 (chunk B's D-11 rebuild of `agent-config-left-panel.tsx`), because both plans touch that same file. Plan 07 replaces the old "Model Deployment" + "Voice Mode" cards with a consolidated VL Instance Summary Card; this plan adds a second, new card below it for the Foundation Model dropdown — it does not re-touch anything Plan 07 built for the VL Instance summary itself.

Purpose: D-14 — the platform currently has no live view of what chat models are actually deployed in the connected AI Foundry project; the only "catalog" that exists (`VOICE_LIVE_MODELS`) is a static dict for Voice Live *realtime* models, and conflating the two is exactly what "两者不再混用" (the two catalogs must not mix) forbids.
Output: A new backend catalog service + admin-scoped endpoint + tests, and a new frontend dropdown component + hook wired into the HCP editor's agent panel.
</objective>
